Manual subscribe

This list is filled by a manual .subscribe() in the component that writes each emitted value into a signal. The subscription is cleaned up with takeUntilDestroyed() so it never leaks when the page is navigated away from.

    @for (post of manualPosts(); track post.id) {
  • {{ post.id }}. {{ post.title }}
    • } @empty {
  • No posts yet — the request is still in flight.
    • }

AsyncPipe

The AsyncPipe (from @angular/common) subscribes to the Observable in the template and unsubscribes automatically when the component is destroyed — no manual cleanup needed. It is the idiomatic way to render an Observable in Angular.

    @for (post of posts$ | async; track post.id) {
  • {{ post.id }}. {{ post.title }}
    • } @empty {
  • Loading posts…
    • }

When to use: Observables whenever data arrives over time — HTTP responses, user input, timers, or any stream. Prefer the AsyncPipe for rendering so Angular owns the subscription lifecycle; reach for a manual .subscribe() only when you need to react to values in component logic, and pair it with takeUntilDestroyed().

Subjects

Subject

New subscribers get nothing from before they joined.

    @for (value of plainLog(); track value) {
  • {{ value }}
    • } @empty {
  • No values received yet.
    • }

BehaviorSubject

New subscribers get the single most recent value.

    @for (value of behaviorLog(); track value) {
  • {{ value }}
    • } @empty {
  • No values received yet.
    • }

ReplaySubject(3)

New subscribers get the last 3 values, in order.

    @for (value of replayLog(); track value) {
  • {{ value }}
    • } @empty {
  • No values received yet.
    • }

When to use: a Subject when you need a shared stream that multiple parts of the app can push into and read from — e.g. a service broadcasting events. Reach for BehaviorSubject when consumers should always have a current value (like a selected item or auth state), and ReplaySubject when late subscribers should catch up on recent history (like a chat or a log).

HttpClient

@switch (fetchStatus()) { @case ('idle') {

Idle — click "Load posts" to fetch from the API.

} @case ('loading') {

Loading…

} @case ('error') {

{{ errorMessage() }}

} @case ('success') {
    @for (post of posts(); track post.id) {
  • {{ post.id }}. {{ post.title }}
    • }
} }

When to use: HttpClient for any HTTP request — GET, POST, PUT, DELETE — to a backend API. It handles JSON parsing, error handling, and request cancellation for you, and its Observables compose with the rest of RxJS. Always surface a loading state and an error state so the UI is never blank or silently broken.
