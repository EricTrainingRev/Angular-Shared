Communication

Angular components talk to each other in one strict pattern: data flows down (parent → child) and events flow up (child → parent). This page uses the MessageBoard child to show both directions, with the traditional decorator API (@Input/@Output) and the modern signal API (input()/output()) side by side.

Parent → child: inputs

The parent passes data down into the child with property binding. Type in the box and the child below re-renders — the value travels from the parent's signal, through [message], into the child.

Child → parent: outputs

The child sends data up by emitting an event. The parent listens with event binding and reacts. Click the child's buttons below.

Round trip: click Rename board in the child. The child emits titleChanged, the parent updates boardTitle, and the new title flows back down into the child's [title]. That is the full loop: up, then down.

Two-way binding: {{ '[(ngModel)]' }}

Two-way binding keeps a value in sync in both directions at once. The {{ '[(ngModel)]' }} syntax (the "banana in a box") is sugar for a property binding plus an event binding: it reads the value into the input and writes it back when the user types.

Your nickname is: {{ nickname() }}

When to use: reach for two-way binding for form inputs where the value and the view must stay in sync. For most other cases, prefer explicit one-way binding ([value] + an event) so the data flow stays easy to trace.
