ng-container

ng-container groups elements under a structural directive without adding a wrapper element to the DOM.

This example uses the older *ngIf structural-directive syntax (rather than the modern {{'@if'}} block) because that is where ng-container is needed: a structural directive must attach to a single host element, and ng-container provides that host without adding a DOM node. Included so you can see the syntax, but you should use the {{'@'}} syntax in your own work.

First grouped line.

Second grouped line.

When to use: reach for ng-container when you need to group multiple elements under a structural directive (*ngIf, *ngFor) but don't want an extra wrapper element in the DOM — for example, to avoid breaking a CSS grid or flex layout that expects direct children. With the modern {{'@'}} control-flow blocks, grouping is handled for you, so ng-container is mainly for the older directive syntax.

ng-template

ng-template defines a template that isn't rendered until you ask for it. NgTemplateOutlet renders it in place.

{{ greeting() }}

When to use: ng-template is for defining a chunk of markup you want to render conditionally or repeatedly in different places — for example, a reusable row or a loading state you can stamp out with NgTemplateOutlet. It's also what the modern {{'@'}} control-flow blocks compile down to internally, so for simple conditional/loop cases you don't write it by hand — but you still use it directly with NgTemplateOutlet for reusable templates.

Normal delivery: in practice, ng-template is usually delivered through NgTemplateOutlet on an ng-container (as shown above), or implicitly by the {{'@'}} control-flow blocks. You rarely render an ng-template directly — it's a definition waiting to be placed somewhere.

Content projection

The Card component projects whatever content you place between its tags. Content marked with [card-header] goes to the header slot; everything else goes to the body.
