Directives

Built-in directives

Angular's built-in directives change how an element looks or behaves. The most common ones toggle CSS classes and inline styles. In modern Angular you apply these with [class] and [style] bindings rather than the older ngClass / ngStyle directives.

Class binding

[class.important] adds the important class to the element only while the bound value is true.

This paragraph is styled by a class binding.

Style binding

[style.width] sets the element's inline width from a value. Here it drives a progress bar.

Progress: {{ progress() }}%

When to use: reach for [class] and [style] bindings to toggle a class or set a style from component state. They are the modern replacement for the older ngClass and ngStyle directives.

Custom attribute directive

appHighlight is a custom attribute directive: it changes how an element looks without changing the DOM structure. Applied as an attribute, it paints the element's background when you hover over it.

Hover over me to see the default highlight.

Hover over me for a cyan highlight.

When to use: write a custom attribute directive when you need to reuse the same look-and-behavior change across many elements — for example, a highlight, a tooltip, or a click-outside handler.

Custom structural directive

appIf is a custom structural directive: it adds or removes an element from the DOM based on a boolean condition. It behaves like a simplified version of the built-in *ngIf.

This content is shown by the custom appIf directive.

When to use: build a custom structural directive when you need to control whether a chunk of the DOM exists based on your own logic — for example, a permission check or a loading state. For most conditionals, the built-in {{ '@if' }} block is usually all you need.

One-way binding

One-way binding moves data from the component class to the template. There are two common forms: interpolation and property binding.

Interpolation

{{ '{{ username() }}' }} renders the signal's value as text.

Hello, {{ username() }}!

Property binding

[disabled] sets the button's disabled property from a value.

When to use: use interpolation to display text and property binding to set an element's property or attribute. Both flow data one way — from the class to the template.

Two-way binding

Two-way binding keeps the component and the view in sync in both directions. [(ngModel)] (the "banana in a box" syntax) updates the signal when you type, and re-renders the text from it.

Your nickname is: {{ nickname() }}

When to use: use [(ngModel)] for form inputs where the value and the component state must stay synchronized — for example, a search box or a settings field. It requires importing FormsModule in the component's imports array.
